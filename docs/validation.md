# Проверки

Основная команда из корня проекта:

```bash
python scripts/check.py --rebuild
```

Нужны зависимости из `requirements-dev.txt`, Node.js 22 и Bash. Скрипт не обращается к Kubernetes, Ollama, SIM или Gitea и не требует секретов. Проверки вызываются также из GitHub Actions.

## Что проверяется

| Проверка | Что она обнаруживает |
|---|---|
| Тесты сборщика требований | Неправильные ветки согласований, checkpoints и блокировка при красном review |
| Тесты downstream Function-блоков | Ошибки обработки ответов API, guards и веток записи |
| Проверка графов | Недостижимые блоки, некорректные Loop/Condition-связи |
| Компиляция JavaScript | Синтаксические ошибки в Function/Condition после подстановки данных |
| Межworkflow-контракты | Несогласованные поля, версии схем и CI callback |
| Export tests | Подмена owner/repo, отказ на недопустимом имени, сохранность исходных шаблонов |
| Bash, JSON и YAML | Синтаксис файлов проекта |
| FastAPI tests | Health, расчёт, ошибки, OpenAPI и заголовки эталонного API |
| Проверка исходников | Типичные секреты, локальные файлы доступа и неработающие ссылки |
| Rebuild | Возможность собрать и проверить оба комплекта из текущего checkout |

Проверка credential patterns — дополнительная защита от случайной публикации, а не полноценный аудит всех возможных секретов. Tests не доказывают безопасность исполнения AI-кода в privileged runner.

## Сборка workflow

В `strict` исходными blueprint являются версионированные JSON вместе с Python-сборщиками. `build_fastapi_system.py` применяет изменения контрактов и guards к этим blueprint. `build_w1.py` также содержит отдельный сборщик первого workflow, который тестируется независимо.

Demo собирается из общих блоков strict и собственного Python-кода. У него нет внешней зависимости от папки Downloads или соседней старой версии проекта. ID блоков и export timestamps при сборке могут меняться; воспроизводимость здесь означает сборку валидного графа и контрактов, а не побайтовое совпадение JSON.

По умолчанию `check.py` читает отслеживаемые экспорты. `--rebuild` собирает копию во временном каталоге, не переписывая рабочие файлы.

## Что остаётся отдельной проверкой

Импорт и deployment в конкретной версии SIM, доступ модели из её backend, права PAT, реальное выполнение Docker/сканеров и полный цикл PR → CI → repair проверяются по [сценарию](demo.md). Результат GitHub Actions подтверждает локальные проверки репозитория, а не развёртывание всей лаборатории.
